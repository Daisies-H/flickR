# Outage Concierge

A customer assistant for storm outages (HackOHI/O 2026 AEP challenge). Pick an anonymous location, set a damage scenario, and see outage risk, a restoration range, preparation tips, alert rules, sample messages, and an AI chat that explains the numbers.

Stack: React + Vite + TypeScript + Tailwind, plus a small Express server whose only job is to call the Claude API for the chat.

## Setup

1. Install Node 20 or newer.
2. In this folder run: `npm install`
3. Copy `.env.example` to `.env` and add your key:
   ```
   ANTHROPIC_API_KEY=your-key-here
   CLAUDE_MODEL=claude-sonnet-5-5
   ```
   The key is read only by the server (`server/index.ts`) and is never sent to the browser. `.env` is in `.gitignore`.
4. Run: `npm run dev`
   - App: http://localhost:5173 (Vite proxies `/api` to the server on port 3001)

If no key is set, or the API call fails, the chat shows a friendly message and a fallback answer built from the same facts, so the demo still works.

Other commands:
- `npm test` runs the unit tests (includes the pole case: 6.8 / 10.7 / 17.6 hours, shown as "roughly 7 to 18 hours").
- `npm run build` type-checks and builds to `dist/`; `npm start` then serves the build and the API together.

## Where things are

- `src/lib/calc.ts`: all calculations, alert rules, tips, messages, and the chat "facts" object (pure functions).
- `src/lib/calc.test.ts`: unit tests.
- `src/components/`: sidebar, lightbulb, metric cards, the three columns, chat, sample messages, limits.
- `server/index.ts`: the chat endpoint and the system prompt.
- `app_data.json`: the only data source, bundled into the front end. All numbers are computed in the browser, so sliders update instantly.

## How the data file was produced

`app_data.json` is generated by the Python scripts in this folder:

1. `train_risk.py` trains the risk model on past damage records and writes `poles_risk.csv` and `risk_model.joblib`.
2. `restore.py` holds the labor hours per item (from `Install_Labor_HackOHIO.xlsx`), the 4.5 indirect labor multiplier, and the hard-access adder.
3. `upstream.py` builds each location's chain of protective devices up to the substation.
4. `export_for_app.py` picks 60 anonymous locations (20 High, 20 Medium, 20 Low), computes the factors and "typical" values, and writes `app_data.json`. It ends with a privacy check (no premise IDs, addresses, coordinates, or facility names).

## Privacy

Only anonymous labels ("Location 1001") are shown. No addresses, customer or premise IDs, coordinates, or facility names are displayed, and chat content is not logged.

## Limits

See "How this works and limits" in the app. In short: the risk model is useful but modest (AUC 0.71 on unseen map areas), no weather data was used, restoration times are a calculation with assumptions, and alert thresholds are challenge assumptions, not utility policy.
